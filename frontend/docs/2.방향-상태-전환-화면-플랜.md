# Quiet Path 방향 전환 화면 플랜 (v1)

## Summary

이 문서는 `ACTIVE 0개 허용`과 `currentDirection = null 가능`을 포함한 최신 제품 규칙에 맞춰, 프론트 화면 1~6번의 UX/상태/문구를 정리한 디자인 가이드다.  
목표는 `방향 종료`와 `새 방향 시작`을 분리하고, 사용자가 원할 때 쉬는 시간을 가질 수 있게 만드는 것이다.

---

## 0. 핵심 규칙 (ERD 정합성 기준)

- 사용자는 동시에 `ACTIVE` 방향을 최대 1개까지 가질 수 있으며, 0개일 수도 있다.
- `review_at`은 AI 회고 열람 가능 시점이다.
- 원본 기록(Record)은 항상 조회 가능하다.
- 잠금 대상은 AI 회고 결과물(`path_summaries`)만이다.
- 방향이 `COMPLETED`가 되어야 `지나온 방향`으로 이동한다.
- `PENDING` 같은 별도 path 상태는 두지 않는다.

---

## 1. 화면 1: 현재 방향 화면 (DirectionView)

### 목적

- 사용자가 현재 방향의 진행 상태를 확인한다.
- `방향 종료`를 독립 액션으로 수행한다.
- 종료 후 바로 새 방향을 강제하지 않는다.

### 주요 변경

- 기존 버튼 `새로운 방향으로 수정하기`를 분리한다.
- 기본 주요 CTA:
  - `현재 방향 마무리하기`
- 보조 CTA:
  - `지나온 방향들 바로가기`
- 선택 보조 CTA:
  - `방향 내용 수정` 또는 `회고 날짜 수정` (정책 허용 시)

### 비활성/휴지 상태

- `currentDirection = null`인 경우 이 화면도 빈 상태를 정상적으로 표현해야 한다.
- 상태 메시지:
  - `지금 진행 중인 방향이 없어요.`
  - `잠시 쉬어가도 괜찮아요. 원할 때 새 방향을 시작해요.`
- 주요 CTA:
  - `새 방향 시작하기`
- 보조 CTA:
  - `지나온 방향들 바로가기`

### 인터랙션

- `현재 방향 마무리하기` 클릭 시 확인 모달:
  - 제목: `이 방향을 마무리할까요?`
  - 본문: `마무리 후 새 방향은 원할 때 시작할 수 있어요.`
  - 버튼: `취소` / `마무리하기`

## 2. 화면 2: 쉬는 상태 화면 (ACTIVE 0개)

### 목적

- 사용자가 방향 종료 후 잠시 멈추는 상태를 명확히 보여준다.
- 다음 행동을 `새 방향 시작`으로 안내한다.

### 적용 위치

- HomeView
- CurrentPathStrip
- DirectionView 빈 상태

### UI 상태

- 상태 메시지:
  - `지금은 잠시 쉬고 있어요.`
  - `원할 때 새 방향을 시작해요.`
- 주요 CTA:
  - `새 방향 시작하기`
- 보조 CTA:
  - `지나온 방향 보기`

### 주의

- 쉬는 상태는 오류 상태가 아니라 정상 상태로 표현한다.
- 비어 있는 화면 느낌보다, 휴지기/정리 시간의 톤으로 디자인한다.
- `ACTIVE null` 같은 표현은 사용하지 않는다.
- 디자이너 문구 기준으로는 `진행 중인 방향이 없는 상태` 또는 `쉬는 상태`라고 표현한다.

---

## 3. 화면 3: 기록 작성 진입 제어 (LogEditor)

### 목적

- 방향 없이 기록이 저장되는 문제를 막는다.

### 규칙

- `ACTIVE` 방향이 없으면 기록 작성 화면 진입 불가
- 기존의 `directionQuestion: '방향 없음'` 저장 흐름 제거

### UX

- 기록 버튼 클릭 시:
  - 안내: `기록하려면 먼저 방향을 시작해 주세요.`
  - 액션: `새 방향 시작하기`

---

## 4. 화면 4: 지난 방향 상세 + AI 회고 캡슐 (PastDirectionsView)

### 목적

- 지난 방향의 원본 기록은 항상 열람 가능하게 유지한다.
- AI 회고만 `review_at` 기준으로 잠금/해제를 처리한다.

### 카드/버튼 상태

- 잠금 상태 (`now < review_at`):
  - `YYYY.MM.DD 까지 회고가 잠겨있어요`
  - 비활성 버튼
- 열람 가능 + 생성 전/생성 중:
  - `AI 회고 캡슐 준비 중`
  - 로딩 표시
- 열람 가능 + 생성 완료:
  - `AI 회고 캡슐 열기`
  - 클릭 시 회고 본문 표시

### 네이밍 가이드

- 기능형 이름만 쓰지 않고 캡슐 감성을 유지한다.
- 추천 조합:
  - 타이틀: `AI 회고 캡슐`
  - 설명: `review_at 이후 열리는 방향 리포트`

---

## 5. 화면 5: 온보딩/새 방향 시작 화면 재사용

### 목적

- 온보딩과 쉬는 상태의 `새 방향 시작` 경험을 같은 폼으로 통일한다.

### 폼 구성

- 카테고리 선택 (`category_code`)
- 방향 제목 (`direction_name`)
- 방향 설명 (`direction_text`)
- 회고 시점 (`review_at`, 필수)

### 엔트리 포인트

- 첫 가입 후 온보딩
- 쉬는 상태에서 `새 방향 시작하기` 클릭

### 완료 후 동작

- 새 path 생성
- `status = ACTIVE`
- Home으로 복귀

---

## 6. 화면 6: 상태 전이와 액션 분리 (앱 로직 대응)

### 목적

- UI와 상태 전이 규칙이 정확히 맞물리게 한다.

### 전이 규칙

1. 현재 방향 마무리:
   - `ACTIVE -> COMPLETED`
   - `completed_at` 기록
   - `currentDirection = null` 상태 가능
2. 새 방향 시작:
   - `ACTIVE 0개` 상태에서만 생성
   - 새 path는 `ACTIVE`
3. AI 회고 노출:
   - `now >= review_at` 이후만 버튼 활성화
   - 최신 `DONE` 버전 표시

### 구현 가이드

- 기존 단일 액션 `updateDirection()`를 분리:
  - `finishCurrentDirection()`
  - `startNewDirection()`

---

## Gemini 전달용 디자인 체크리스트

- 필수 상태 3가지를 모두 포함한다:
  - `ACTIVE 있음`
  - `ACTIVE 없음(쉬는 상태)`
  - `Past + AI 회고 잠금/해제`
- `ACTIVE null`처럼 DB로 오해될 표현 대신 `ACTIVE 0개 가능`, `currentDirection이 비어 있을 수 있음`으로 이해한다.
- 버튼 의미를 혼합하지 않는다:
  - `마무리하기`와 `새 방향 시작하기`를 분리
- 원본 기록 잠금 UI를 넣지 않는다.
- 잠금 UI는 AI 회고 영역에만 적용한다.
- 문구 톤은 압박형이 아니라 선택형으로 유지한다.
