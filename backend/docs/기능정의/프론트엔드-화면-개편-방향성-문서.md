# Quiet Path v1.5 프론트엔드 화면 개편 방향성 문서

## Summary

이 문서는 Antigravity 툴에서 프론트엔드 화면 개편을 진행할 때 기준이 되는 방향성 문서다.

Quiet Path의 v1.5 프론트 개편 목표는 다음과 같다.

- 기존의 차분하고 부드러운 색감은 유지한다.
- 앱을 더 정리되고, 더 귀엽고, 더 쓰고 싶게 만든다.
- 무거운 철학 문구 중심 UI에서 벗어나 행동 중심 UI로 바꾼다.
- 기록, 월간 회고, 방향 요약이 자연스럽게 이어지는 경험을 만든다.
- 감정/스티커형 재미를 우선 적용한다.
- 커뮤니티는 축소하되 존재감은 유지한다.

이 개편은 백엔드 재설계가 아니라, 프론트 화면 구조, 문구, 상호작용, 감정 표현 방식, 정보 밀도 조정에 집중한다.

---

## 1. 제품 감성 방향

Quiet Path는 아래 감정을 유지해야 한다.

- 차분함
- 부드러움
- 정리된 느낌
- 따뜻함
- 회고하고 싶어지는 감정
- 조용하지만 재미있는 감정

Quiet Path는 아래 방향으로 가면 안 된다.

- 시끄러운 SNS 느낌
- 과한 생산성 앱 느낌
- 사진앱/앨범앱 중심 UI
- 과도한 게임화
- 무겁고 추상적인 문장만 반복되는 분위기

핵심은 다음이다.

`조용하지만, 메모장보다 훨씬 기록하고 싶어지는 앱`

---

## 2. 반드시 유지할 것

### 2.1 색감

현재 Quiet Path의 색감은 유지한다.

- 부드러운 배경
- 연한 포인트 컬러
- 안개 낀 듯한 잔잔한 무드
- 흰색/미스트톤/포인트톤 중심 조합

변경 원칙

- 색상 체계 자체를 갈아엎지 않는다.
- 밝고 튀는 원색 위주로 바꾸지 않는다.
- 기존 감성 위에 아이콘, 스티커, 카드 구조, 타이포 위계만 보강한다.

### 2.2 앱의 중심 축

홈의 중심 경험은 끝까지 아래 4개다.

- Path
- 오늘 기록
- 월간 리포트
- Path 요약

커뮤니티는 존재하지만 메인 중심축이 아니다.

---

## 3. 프론트 개편 핵심 목표

### 3.1 홈을 더 정리하기

현재 홈은 문구 중심이고 추상적인 인상이 강하다.  
개편 후 홈은 아래 질문에 바로 답해야 한다.

- 지금 내가 어떤 Path 위에 있는가?
- 오늘 무엇을 할 수 있는가?
- 이번 달 나는 어떤 흐름으로 가고 있는가?
- 최근 남긴 감정과 장면은 무엇인가?

### 3.2 더 귀엽고 더 가볍게 만들기

재미는 필요하다.  
다만 게임처럼 과장하지 않고, `감정/스티커형 재미`를 중심으로 넣는다.

핵심 메커니즘

- 무드 스티커
- 작은 배지
- 귀여운 상태 라벨
- 기록 완료 시 만족감 있는 피드백
- 감정 선택의 즐거움

### 3.3 회고를 더 잘 꺼내보이게 만들기

기록은 쌓이는 것이 아니라 다시 열어보게 만들어야 한다.  
그래서 화면은 아래를 강화해야 한다.

- 월간 보기
- 이미지 1장 기반 회고
- Monthly Photo Timeline
- Path 요약 카드
- 감정 흐름이 보이는 구조

---

## 4. 톤앤매너 변경 방향

현재 앱은 아래 성격이 강하다.

- 철학적
- 추상적
- 문구가 길고 비슷함
- 행동 유도보다 설명이 많음

개편 방향은 아래와 같다.

- 더 짧고
- 더 생활감 있고
- 더 친근하고
- 더 행동 중심적으로

### 줄일 표현

- 어디로 향하는가
- 방향을 잃지 않는 것이 중요합니다
- 이 방향으로 살고 있었는지를 돌아봅니다
- 지나치게 비슷한 철학 문장의 반복

### 늘릴 표현

- 오늘 마음은 어땠나요?
- 한 줄만 남겨도 괜찮아요
- 오늘의 장면을 남겨볼까요?
- 이번 달의 조각들을 다시 볼까요?
- 비슷한 기분의 기록을 둘러보세요
- 오늘도 하나 남겨볼까요?

원칙

- 문장은 짧게
- 버튼 라벨은 직관적으로
- 설명보다 행동 유도 먼저

---

## 5. 재미 요소 우선순위

v1.5의 재미 우선순위는 아래와 같다.

1. 감정/스티커형
2. 커뮤니티형
3. 수집형

### 5.1 감정/스티커형

가장 먼저 반영해야 하는 재미 요소다.

핵심 개념

- 무드 스티커북
- 오늘의 감정을 고르는 즐거움
- 월간 회고에서 감정들이 모여 보이는 경험
- 기록 카드와 월간 회고에서 감정이 시각적으로 살아 있는 구조

### 5.2 커뮤니티형

커뮤니티는 줄이되 없애지 않는다.

v1.5 커뮤니티는 아래까지만 표현한다.

- 공유된 기록 피드
- 최신순
- 카테고리 필터
- 피드를 둘러보고 공감하고 싶어지는 UI

### 5.3 수집형

칭호/뱃지/수집형은 v1.5에서 크게 드러내지 않는다.  
존재감은 약하게만 두고, 본격 확장은 후속 버전으로 둔다.

---

## 6. 감정/스티커 디자인 방향

v1.5의 핵심 시각 재미는 `무드 스티커북`이다.

### 예시 무드

- 포근
- 멍함
- 반짝
- 잔잔
- 버팀
- 두근

### 표현 원칙

- 단순 emoji 텍스트 나열 금지
- 작은 스티커 칩, 배지, 라벨 형태로 보여주기
- 귀엽지만 유치하지 않게
- 기존 색감과 어울리게
- 홈, 기록, 월간 리포트, 커뮤니티에 일관되게 적용

### 프론트에서 필요한 것

- mood label
- mood icon
- mood color
- selected / unselected 상태
- 리스트형 / 카드형 / 작은 배지형 변형

## 7. 화면별 개편 방향

## 7.1 Home

### 목표

- 첫 화면에서 앱이 더 정리되어 보이게 만들기
- 오늘 할 수 있는 행동이 바로 보여야 한다
- 기록과 회고를 자연스럽게 이어줘야 한다

### 구성 방향

상단

- 날짜
- 현재 Path 이름 또는 질문
- 최근 무드 스티커

메인 카드

- 오늘의 질문 1개
- 현재 Path 상태
- 오늘 기록 여부

메인 액션 3개

- 기록 남기기
- 이번 달 보기
- 지난 흐름 보기 또는 피드 둘러보기

하단 요약

- 이번 달 기록 수
- 방향 유지율 요약
- 최근 한 줄 회고
- 최근 사진이 있으면 작은 썸네일

### 금지

- 긴 철학 문장 블록
- 홈 전체가 설명문처럼 보이는 구조
- 너무 많은 카드가 같은 위계로 나열되는 구조

---

## 7.2 Log Editor

### 목표

- 기록이 더 쉽고 덜 부담스럽게 느껴지게 만들기
- 감정 선택이 재밌게 느껴지게 만들기
- 저장 시 만족감이 느껴지게 만들기

### 구성 방향

- 오늘의 질문
- 오늘의 장면
- 오늘을 한 단어로
- 내일의 한 걸음
- 무드 스티커 선택
- 이미지 1장 업로드

### UX 원칙

- 입력 구역은 짧고 나뉘어 있어야 한다
- 시각적으로 편안해야 한다
- 저장 버튼은 분명하고 매력적이어야 한다
- 저장 후 작은 피드백이 필요하다
    - 체크
    - 짧은 문구
    - 가벼운 모션

### 이미지 정책 반영

- 이미지 첨부는 최대 1장
- 사진은 기록의 보조 요소로 보이게
- 업로드 UI는 간단하고 직관적으로

---

## 7.3 Records / 월간 보기

### 목표

- 기록을 더 보기 좋게
- 사진과 감정이 회고를 도와주게
- 월간 단위로 다시 꺼내보기 쉽게

### 기본 방향

기록 탭의 기본은 `월간 보기` 중심으로 구성한다.

구성

- 월 요약
- 날짜별 기록 리스트
- 필요 시 월 내 섹션 구분

Record 카드 우선순위

1. 날짜
2. mood
3. oneWord
4. scene preview
5. 사진 썸네일

### 카드 성격

- 읽기 쉬워야 함
- 너무 많은 정보를 한 카드에 넣지 않음
- 사진은 강조하되 메인이 되지 않게
- 감정 스티커가 카드의 시각 기준점 역할을 하게

---

## 7.4 Record 상세

### 목표

- 하루를 다시 느끼게 하는 회고 화면 만들기
- 사진과 텍스트가 잘 균형 잡히게 만들기

### 구성

- 날짜
- mood + oneWord
- sceneText
- image
- tomorrowText
- tags

### 디자인 방향

- 사진이 있으면 메인 장면처럼 보이게 하되,
  사진앱처럼 보이지는 않게 한다.
- mood와 oneWord가 상단에서 하루의 분위기를 요약해줘야 한다.
- 본문은 읽기 편한 간격과 폭으로 정리한다.

---

## 7.5 Monthly Report

### 목표

- 단순 통계가 아니라 회고 화면처럼 느껴지게 만들기
- 감정, 사진, 하이라이트, 흐름이 함께 보이게 만들기

### UI 우선 구조

1. 방향 유지율
2. 감정 분포
3. Monthly Photo Timeline
4. 기억할 기록 3개
5. Top Tags
6. Path 흐름
7. 날짜별 기록 리스트

### 원칙

- 숫자만 많은 화면 금지
- 감정과 장면이 같이 보여야 함
- Monthly Photo Timeline은 핵심 시각 섹션으로 취급

---

## 7.6 Monthly Photo Timeline

### 목표

- 이번 달의 장면들을 다시 꺼내보게 만들기
- 사진을 소비하는 게 아니라 회고의 앵커로 쓰기

### 위치

- Monthly Report 내부

### 구성 방향

- 이미지가 첨부된 Record만 사용
- 날짜 기반 흐름이 보이게 배치
- 각 카드 또는 썸네일에 아래를 작게 연결 가능
    - 날짜
    - mood
    - oneWord

### 정렬 기준

- 기본은 월 내 날짜순
- 개수가 많아질 경우 최신 12개 우선
- 단, UI는 시간 흐름이 깨져 보이지 않게 정돈

### 금지

- 앨범앱처럼 보이는 전체 그리드
- SNS 사진 피드처럼 보이는 구조
- 사진만 크게 소비하는 느낌

---

## 7.7 Path / Past Directions / Summary

### 목표

- 방향성과 회고라는 Quiet Path의 정체성을 유지
- 문구는 더 덜 무겁고 더 친근하게
- AI 요약은 더 보고 싶게

### 개편 방향

- Path 화면은 정보가 더 정리되어 보여야 함
- Past Directions는 회고 아카이브 느낌이 나야 함
- Path Summary 카드는 결과를 읽고 싶게 생겨야 함
- 잠금 상태 / 해제 시점 / 요약 생성 상태는 더 직관적으로 설명되어야 함

---

## 7.8 Community

### 목표

- 조용히 둘러보게 만들기
- 나도 기록 남기고 싶어지게 만들기
- 핵심 경험을 방해하지 않게 만들기

### v1.5 범위

- 공유된 기록 피드까지만
- 최신순
- 카테고리 필터
- 커서 페이징 전제 UI

### 디자인 방향

- SNS처럼 소란스럽지 않게
- 공감, 공유 흔적, 무드 스티커, 한 줄 내용 중심
- 기록의 분위기를 느끼는 피드
- 홈보다 앞에 나오지 않음

---

## 8. 정보 구조 원칙

프론트 개편 시 모든 화면은 아래 원칙을 지켜야 한다.

- 한 화면에 핵심 메시지는 1개
- 카드 위계는 분명하게
- 같은 크기의 카드가 반복되어 지루해지지 않게
- 모바일에서 손가락으로 쉽게 누를 수 있게
- 텍스트보다 구조로 이해되게
- 긴 설명보다 상태와 행동을 먼저 보여주기

---

## 9. 인터랙션 원칙

- 저장, 선택, 완료, 펼치기, 잠금 해제 같은 상태 변화는 가볍게 느껴져야 한다.
- 너무 요란한 애니메이션은 피한다.
- 작은 반응과 만족감을 준다.
- 감정 선택과 기록 저장은 특히 부드럽고 안정적으로 느껴져야 한다.

예시

- 스티커 선택 시 부드러운 확대/채움
- 저장 완료 시 짧은 체크 모션
- 카드 펼침은 천천히
- 잠금 상태는 불편보다 기대감 중심으로 표현

---

## 10. 구현 시 유의사항

- 기존 색감 유지가 최우선이다.
- 새로운 재미 요소를 넣더라도 전체 무드를 깨지 않는다.
- 문구는 추상성보다 사용성을 우선한다.
- 사진은 보조 요소이지 메인 소비 요소가 아니다.
- 커뮤니티는 작게 유지한다.
- Quiet Path가 범용 일기앱처럼 보이지 않게 한다.

---

## 11. Antigravity 작업 가이드

Antigravity에서 프론트 작업 시 아래 결과를 목표로 한다.

### 기대 결과

- 홈 화면이 더 정돈되어 있다.
- 기록 작성이 더 쉽고 귀엽다.
- 감정/스티커 시스템이 일관되게 적용된다.
- 월간 회고 화면이 훨씬 매력적이다.
- Monthly Photo Timeline이 회고 기능으로 자연스럽게 들어간다.
- 커뮤니티는 작지만 살아 있다.
- 앱 전체가 더 사용하고 싶어지는 느낌을 준다.

### 하지 말아야 할 것

- 기존 색감 전면 교체
- 과한 SNS UI
- 사진앱 같은 전개
- 게임화 과잉
- 텍스트 과다
- 철학 문구 반복
