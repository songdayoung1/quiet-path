# Quiet Path v1.5 앱 방향성 문서

## Summary

Quiet Path는 범용 일기 앱이 아니라 `회고가 하고 싶어지는 앱`이다.  
핵심 경험은 `Path 설정 → Daily Record → Monthly Review → Path Summary` 흐름에 있으며, 모든 기능은 이 회고 루프를 강화하는 방향으로 설계한다.

v1.5에서는 기록 구조를 더 선명하게 만들고, 월간 회고 경험을 강화하며, 감정/스티커 기반의 재미를 추가한다.  
커뮤니티는 유지하지만 핵심 경험이 아닌 보조 경험으로 둔다.

---

## 1. 제품 정의

Quiet Path는 단순히 하루를 적어두는 앱이 아니다.  
사용자가 자신의 방향을 정하고, 하루를 가볍게 남기고, 한 달과 한 흐름을 다시 돌아보게 만드는 회고 중심 기록 앱이다.

핵심 목표는 아래와 같다.

- 메모장이 아니라, 다시 열어보고 싶은 기록 경험 만들기
- 텍스트만 쌓이는 앱이 아니라, 감정과 장면이 남는 회고 경험 만들기
- 너무 무겁지 않지만, 가볍게 소비되지도 않는 기록 경험 만들기
- 기록이 통계, 요약, 회고로 이어지는 구조 만들기

---

## 2. 핵심 사용자 흐름

Quiet Path의 중심 흐름은 아래와 같다.

1. Path 설정
2. 오늘의 Record 작성
3. 월간 회고 확인
4. Path 종료 후 요약 확인

이 흐름이 앱의 중심이며, 홈 화면과 주요 진입 구조도 이 흐름을 기준으로 유지한다.

핵심 도메인

- Path
- Record
- Monthly Report
- Path Summary

---

## 3. 제품 원칙

### 3.1 Quiet Path는 회고 앱이다

Quiet Path는 생산성 앱이나 목표 달성 앱이 아니다.  
모든 기능은 `내가 지금 어떤 방향으로 살고 있었는지`를 다시 보게 만드는 데 초점을 둔다.

### 3.2 구조화된 기록을 유지한다

Record는 자유 일기보다 `회고 가능한 기록 단위`여야 한다.  
그래서 사건, 감정, 다음 행동이 남는 구조를 유지한다.

### 3.3 재미는 넣되 정체성은 잃지 않는다

재미는 필요하다.  
하지만 SNS처럼 시끄럽거나 게임처럼 과도한 보상 구조로 가면 Quiet Path의 정체성이 흐려진다.

v1.5의 재미 우선순위는 아래와 같다.

1. 감정/스티커형
2. 커뮤니티형
3. 수집형

### 3.4 홈의 중심은 끝까지 내 기록 경험이다

커뮤니티를 넣더라도 홈의 중심은 항상 아래 네 가지여야 한다.

- Path
- 오늘 기록
- 월간 리포트
- Path 요약

---

## 4. Path 방향성

Path는 사용자가 일정 기간 동안 집중하는 방향이다.

핵심 의미

- 지금 내가 무엇을 향하고 있는지
- 이번 기간을 어떤 질문으로 살아가고 있는지
- 언제 다시 돌아볼 것인지

핵심 필드

- `id`
- `user_id`
- `category_code`
- `name`
- `key_question`
- `description`
- `start_at`
- `anchor_at`
- `closed_at`
- `created_at`

정책

- 사용자당 Active Path는 1개만 허용한다.
- 새 Path를 만들기 전에 현재 Path는 명시적으로 종료해야 한다.
- 현재 저장소 기준으로 Path 종료일은 별도 `end_date` 고정 컬럼보다 `anchor_at` 또는 `closed_at` 해석값으로 다룬다.

---

## 5. Record 방향성

Record는 단순 일기가 아니라 `reflection unit`이다.  
하루를 남기는 최소 단위이며, 통계, 회고, AI 요약의 입력 데이터가 된다.

핵심 필드

- `id`
- `user_id`
- `path_id`
- `record_date`
- `scene_text`
- `one_word_text`
- `tomorrow_text`
- `mood_code`
- `image_url` 또는 향후 저장 방식에 따른 이미지 참조값
- `visibility`
- `created_at`
- `updated_at`

제약

- `UNIQUE(user_id, record_date)`
- 하루에 Record는 1개만 존재한다.

Record의 의미 구조

- `sceneText`: 오늘 어떤 장면이 있었는지
- `oneWordText`: 오늘 하루를 한 단어로 요약
- `moodCode`: 감정 코드
- `image`: 그날의 장면을 기억하게 하는 사진
- `tomorrowText`: 내일의 작은 행동
- `tags`: 반복되는 패턴 분석용

---

## 6. Record 수정 정책

Record는 그날의 흔적이라는 성격을 유지하되, v1.5에서는 사용 편의를 위해 수정 가능 기간을 조금 더 넓게 둔다.

정책

- Record 수정 가능 기간은 `작성일 포함 7일`이다.
- 수정 가능 대상:
    - `sceneText`
    - `oneWordText`
    - `tomorrowText`
    - `moodCode`
    - `tags`
    - `image`
- 7일이 지나면 Record는 읽기 전용이 된다.
- 공유된 기록은 직접 수정할 수 없다.
- 공유된 기록을 수정하려면 아래 순서를 따른다.
    1. 공유 해제
    2. 수정
    3. 필요 시 재공유

의도

- 기록은 너무 쉽게 계속 바뀌지 않도록 한다.
- 동시에 사용자가 며칠 안에 회고를 조금 다듬을 수 있는 여유는 제공한다.
- 공유된 기록은 커뮤니티 신뢰를 위해 수정 제한을 둔다.

---

## 7. Record 이미지 정책

이미지는 기록의 중심이 아니라 `회고를 도와주는 장면 앵커`로 사용한다.

원칙

- Record당 이미지 최대 1장
- 이미지 첨부는 선택 사항
- 사진 중심 UI로 확장하지 않음
- SNS형 사진 피드 구조로 확장하지 않음
- 이미지 수정 가능 기간은 Record 수정 정책과 동일하게 `작성일 포함 7일`
- 공유된 기록의 이미지는 직접 수정 불가

UI 우선순위

1. 날짜
2. mood
3. oneWord
4. scene preview
5. 사진 썸네일

의도

- 사진 앱처럼 보이게 만드는 것이 목적이 아니다.
- 텍스트만으로 흐려질 수 있는 기억을 더 잘 꺼내보게 만드는 보조 요소로 사용한다.

---

## 8. 감정/스티커 방향성

v1.5의 핵심 재미 메커니즘은 `무드 스티커북`이다.

목표

- 기록 과정이 더 귀엽고 부담 없게 느껴지게 하기
- 감정을 공통 언어처럼 홈, 기록, 리포트, 커뮤니티에 연결하기
- 회고 화면이 숫자와 텍스트만 있는 구조가 되지 않게 하기

예시 무드

- 포근
- 멍함
- 반짝
- 잔잔
- 버팀
- 두근

운영 기준

- `moodCode`는 v1.5에서 자유 입력을 허용하지 않는다.
- `moodCode`는 enum 또는 서버 상수로 관리한다.
- 프론트엔드는 `label / icon / color` 매핑을 담당한다.

사용 위치

- 홈의 최근 감정 상태
- 기록 작성 시 감정 선택
- 기록 카드
- 월간 리포트
- 공유 기록 피드

## 9. Monthly Report 방향성

Monthly Report는 Quiet Path의 핵심 회고 화면이다.  
단순 리스트가 아니라 `요약 + 감정 흐름 + 장면 회고 + 기록 하이라이트` 구조여야 한다.

목적

- 한 달 동안 내가 얼마나 살아냈는지 보기
- 어떤 감정과 패턴이 반복되었는지 보기
- 어떤 장면이 기억에 남는지 다시 보기
- 다음 Path를 시작할 감각을 얻기

방향 유지율 공식

`consistencyRate = recordDays / eligibleDays`

정의

- `recordDays`: 해당 월 기록 수
- `eligibleDays`: 해당 월 Active Path가 존재했던 날짜 수

Path가 없는 기간은 제외한다.

## 10. Monthly Photo Timeline

Monthly Photo Timeline은 v1.5에서 반드시 포함하는 회고 요소다.

위치

- Monthly Report 내부

목적

- 이번 달의 장면들을 다시 꺼내보는 시각적 회고 타임라인

기준

- 해당 월에 이미지가 첨부된 Record

구성

- `recordId`
- `imageUrl`
- `date`
- 필요 시 `moodCode`
- 필요 시 짧은 프리뷰

정렬 기준

- 기본 노출은 `월 내 날짜순`으로 보여준다.
- 단, 이미지 기록이 많아질 경우 기본 노출 개수는 `최신 12개`로 제한한다.
- 최신 12개를 추린 뒤에도 UI에서는 날짜 흐름이 어색하지 않도록 정렬을 정돈해서 보여준다.

정책

- 클릭 시 Record 상세 화면으로 이동
- 별도 사진 SNS 탭으로 확장하지 않는다

의도

- 사진 중심 소비가 아니라, 월간 회고 안에서 기억 복원력을 높이는 역할을 한다.

## 11. 월간 리포트 UI 우선 구조

Monthly Report는 아래 순서로 구성한다.

1. 방향 유지율
2. 감정 분포
3. Monthly Photo Timeline
4. 기억할 기록 3개
5. Top Tags
6. Path 흐름
7. 날짜별 기록 리스트

이 순서는 숫자 요약과 감정적 회고를 균형 있게 보여주기 위한 구조다.

## 12. highlights 선정 기준

Monthly Report의 `highlights`는 프론트와 백엔드가 다르게 해석하지 않도록 고정 기준을 둔다.

선정 우선순위

1. 공유된 기록 우선
2. 이미지가 있는 기록 우선
3. 최신순

의도

- 회고 화면에서 더 보여줄 가치가 큰 기록을 안정적으로 고른다.
- 시각적 장면과 공유 맥락이 있는 기록을 먼저 노출한다.
- 프론트 임의 선택이 아니라 서버 기준으로 일관되게 제공한다.

구성

### Record 상세

- 상세는 하루를 다시 느끼게 한다

## 14. Path Summary 방향성

Path Summary는 한 흐름을 마무리하는 회고 결과다.

목적

- 이 기간의 전체 흐름을 한 번에 돌아보기
- 반복된 감정과 패턴을 정리하기
- 다음 Path를 시작할 질문을 얻기

v1.5에서 AI는 아래 범위에 사용한다.

- Path 종료 후 요약
- 짧은 보조 결과
    - 여정의 별명
    - 반복 감정
    - 다음 질문 추천

- Monthly Report는 캘린더 월 기준 회고이고, Path Summary는 특정 Path 기간 기준 회고다.
- 두 기능은 기준 축이 다르므로 중복 기능이 아니라 상호보완적 기능으로 설계한다.

Monthly Report 전체 본문을 AI로 생성하지는 않는다.

## 15. Community 방향성

커뮤니티는 존재하지만 핵심 경험이 아니다.  
Quiet Path의 중심은 내 회고 경험이며, 커뮤니티는 그것을 보조하는 역할로 둔다.

### v1.5 범위

- 공유된 Record 피드까지만 제공
- 최신순 피드
- 카테고리 필터
- 커서 페이징

### v1.5 제외 범위

- 인기순 정렬
- 댓글
- 알림
- 팔로우
- 본격 SNS형 상호작용

### 역할

- 다른 사람의 조용한 기록을 둘러본다
- 나도 하나 기록하고 싶어지게 만든다
- 핵심 흐름을 방해하지 않는다

### 쿼리/인덱스 관점

Flow 페이지는 축소하더라도 아래 최적화 방향은 유지한다.

- 공유 피드는 `최신순 + 카테고리 필터 + 커서 페이징`을 기준으로 설계한다.
- 현재 인덱스 `(visibility, category_code, shared_at, id)`를 활용하는 방향으로 조회를 맞춘다.
- 실제 구현에서는 EXPLAIN으로 인덱스 활용 여부를 검증한다.
- 인기순 정렬은 후속 버전에서 별도 집계/캐시 전략으로 분리한다.

## 16. 공개 API / 인터페이스 방향

v1.5 기준 핵심 인터페이스 방향은 아래와 같다.

### Record

- `PUT /api/v1/records/today`
- 의미: 오늘 기록 upsert
- 입력:
    - `sceneText`
    - `oneWordText`
    - `tomorrowText`
    - `moodCode`
    - `tags[]`
    - `imageUrl`
- 검증:
    - `sceneText` 또는 `oneWordText` 중 하나 필수
    - tags 최대 3개

- `GET /api/v1/records/today`
- 의미: 오늘 기록 조회

- `POST /api/v1/records/{recordId}/share`
- 의미: 기록 공유

### Monthly Report

- `GET /api/v1/reports/monthly/{yearMonth}`

응답 핵심 구조

- `month`
- `overview`
    - `recordDays`
    - `eligibleDays`
    - `consistencyRate`
    - `pathChangeCount`
- `moods`
- `topTags`
- `photoTimeline`
- `paths`
- `highlights`

## 17. 최종 방향성 문장

Quiet Path는 기록 앱이 아니라 회고 앱이다.

모든 기능은 결국 아래 흐름을 강화해야 한다.

`Path → Record → Review`

기록은 쌓이는 것이 아니라 돌아보게 만들어야 하며,  
사진, 감정, 월간 리포트, Path 요약은 모두 이 회고 경험을 더 선명하게 만드는 방향으로 사용한다.

커뮤니티는 존재하되 작게 유지하고,  
홈의 중심은 끝까지 내 Path, 오늘 기록, 월간 회고, Path 요약에 둔다.

---

## Assumptions / Defaults

- 현재 저장소 구조를 구현 기준으로 삼는다.
- Path의 종료 표현은 `anchorAt`과 `closedAt` 해석을 우선한다.
- Record는 하루 1개 정책을 유지한다.
- Record 수정 가능 기간은 `작성일 포함 7일`로 둔다.
- 공유된 Record는 직접 수정할 수 없다.
- 이미지 정책은 `기록당 1장`으로 고정한다.
- `moodCode`는 자유 입력이 아닌 enum/서버 상수로 관리한다.
- Monthly Photo Timeline은 Monthly Report 내부 기능으로 둔다.
- highlights 선정 기준은 `공유 우선 → 이미지 우선 → 최신순`으로 고정한다.
- 커뮤니티는 공유 기록 탐색까지만 제공한다.
