# Community 상태 동기화 정리

## 1. 목적

커뮤니티에서 같은 기록이 여러 위치에 보여도 상태가 다르게 보이지 않게 만든다.

핵심은 3가지다.

* 같은 `recordId`면 feed와 Top3가 같은 값을 본다.
* 댓글 수는 프론트에서 `+1 / -1`로 계산하지 않고 서버 값을 따른다.
* 댓글 목록은 작업 후 해당 기록의 첫 페이지를 다시 조회해 맞춘다.

## 2. 기준 단위

상태 동기화의 기준은 항상 `recordId`다.

같은 기록이 아래 위치에 동시에 보여도 같은 상태여야 한다.

* feed 카드
* Top3 카드
* 댓글 시트 헤더

동기화 대상 값은 아래 3개다.

* `reactionCount`
* `commentCount`
* `isReacted`

## 3. Top3 기준

Top3도 `path`가 아니라 `record` 기준으로 집계한다.

이유는 간단하다.

* 실제 공감과 댓글은 기록 단위로 붙는다.
* feed 카드도 기록 단위다.
* 댓글 시트도 기록 단위다.

즉 집계 단위와 화면 단위가 모두 `recordId`로 맞아야 동기화가 단순해진다.

## 4. 하트 처리 원칙

하트는 반응 속도가 중요하므로 optimistic update를 허용한다.

흐름:

1. 사용자가 하트를 누른다.
2. 프론트가 현재 화면의 `reactionCount`, `isReacted`를 먼저 바꾼다.
3. 서버 요청이 실패하면 원래 값으로 롤백한다.
4. 같은 `recordId`가 feed와 Top3에 같이 있으면 둘 다 같이 바꾼다.

즉 "같은 기록은 같은 상태"만 지키면 된다.

## 5. 댓글 처리 원칙

댓글은 정합성이 더 중요하므로 optimistic update를 하지 않는다.

흐름:

1. 댓글 작성 / 수정 / 삭제 요청을 보낸다.
2. 서버가 성공하면 해당 `recordId`의 댓글 첫 페이지를 다시 조회한다.
3. 댓글 목록은 재조회 결과로 교체한다.
4. `commentCount`도 서버 응답 기준으로 갱신한다.

여기서 다시 조회하는 대상은 "그 기록의 댓글 목록 첫 페이지"다.
게시글 전체나 feed 전체를 다시 불러오는 것이 아니다.

## 6. 댓글 응답에 `recordId`, `commentCount`를 넣은 이유

댓글 변경 직후 프론트가 추측하지 않게 하려는 목적이다.

서버 응답에 아래 값이 들어가면 좋다.

* `recordId`: 어떤 기록을 갱신해야 하는지 바로 알 수 있다.
* `commentCount`: soft delete 제외 기준의 실제 댓글 수를 바로 알 수 있다.

이 구조의 장점:

* 프론트가 `+1 / -1` 계산을 하지 않아도 된다.
* 같은 `recordId`가 feed와 Top3에 같이 있어도 한 번에 맞출 수 있다.
* 나중에 캐시를 붙여도 "해당 recordId 무효화 후 재조회" 규칙으로 이어가기 쉽다.

## 7. 서버 기준 값

댓글 수는 "활성 댓글 수" 기준이다.

즉 soft delete 댓글은:

* DB에는 남는다.
* 일반 댓글 목록에서는 보이지 않는다.
* `commentCount`에도 포함하지 않는다.

## 8. 카테고리 전환 규칙

카테고리를 바꾸면 아래 상태를 초기화한다.

* 현재 feed 목록
* pagination cursor
* 열린 댓글 시트
* 선택된 댓글 대상 `recordId`

목적은 이전 카테고리의 상태가 다음 카테고리에 섞이지 않게 하는 것이다.

## 9. 구현 체크리스트

### 백엔드

* Top3 응답이 `recordId` 기준인지 확인
* 댓글 작성 / 수정 / 삭제 응답에 `recordId`, `commentCount` 포함
* `commentCount`가 active comment 기준인지 확인

### 프론트

* 같은 `recordId`면 feed / Top3를 함께 갱신
* 하트는 optimistic update + 실패 시 롤백
* 댓글은 성공 후 첫 페이지 재조회
* 카테고리 전환 시 상태 초기화

## 10. QA 기준

아래 4개가 맞으면 상태 동기화는 정상이다.

1. feed에서 하트를 누르면 Top3의 같은 기록도 바로 바뀐다.
2. Top3에서 하트를 누르면 feed의 같은 기록도 바로 바뀐다.
3. 댓글 작성 / 삭제 후 댓글 수가 서버 기준으로 맞는다.
4. 카테고리 전환 후 이전 카테고리의 댓글 시트나 count가 남지 않는다.
