# 기록 공유와 월간 기록 화면 개편 계획

## 1. 배경

- 현재 기록 탭은 전체 기록을 한 번 내려받은 뒤 프론트에서 월별로 필터링한다.
- 기록 카드 메뉴에는 `카카오톡 공유`, `링크 복사` 문구가 있지만 실제 기능은 연결되어 있지 않다.
- 개인 기록 서비스 성격상 공개 링크 중심 공유는 방향과 맞지 않는다.
- 공유 기능은 링크보다 `이미지 카드 내보내기`가 더 자연스럽다.

## 2. 현재 상태 정리

### 기록 조회

- 프론트는 `GET /api/v1/records` 전체 조회 결과를 기준으로 월별 화면을 구성한다.
- 월 이동 UI는 있으나 서버 기준 월별 데이터 바인딩은 아니다.
- 기록 수가 늘어날수록 프론트 계산 비용이 커진다.

### 공유 기능

- 현재 구현된 공유 관련 서버 기능은 `커뮤니티 공개/비공개 전환`이다.
- 외부 공유용 이미지 생성, 파일 저장, 카카오 공유, 링크 복사 기능은 아직 없다.

### 기록 탭 UI

- `앨범 / 기록 / 캘린더` 3개 탭만 있다.
- 기록 탭 안의 정렬 방식, 보기 방식 선택 UI는 없다.
- 캘린더는 월별 시각화 중심이고, 공유/저장 액션은 아직 없다.

## 3. 목표

### 핵심 목표

- 기록 화면을 월별 API 기준으로 재구성한다.
- 링크 복사는 제거한다.
- 기록 단건/다건을 이미지 카드로 내보낼 수 있게 한다.
- `카카오톡 공유`라는 표현보다 `카드 내보내기` 중심 UX로 정리한다.

### 기대 효과

- 월별 기록 화면의 데이터 정합성이 높아진다.
- 기록 공유 경험이 서비스 방향과 더 잘 맞는다.
- 개인 기록을 외부에 보여줄 때 링크가 아니라 결과물 중심으로 공유할 수 있다.

## 4. 기능 방향

### 4-1. 공유 기능 방향

#### 링크 복사

- 제거한다.
- 로그인 기반 개인 기록 서비스에서는 공개 링크 UX의 의미가 약하다.

#### 단건 공유

- 기록 1건을 카드 이미지로 내보낸다.
- 우선순위는 `이미지 저장`과 `공유하기(Web Share 가능 시)`다.
- 명칭은 `카드 내보내기`가 적절하다.

#### 다건 공유

- 1차 대상은 `월간 캘린더 카드`다.
- 이후 확장으로 `선택 기록 묶음 카드`를 추가할 수 있다.
- 카카오톡 공유는 별도 고유 기능이 아니라, 생성된 이미지를 공유하는 단계로 본다.

### 4-2. 기록 탭 방향

#### 기록 탭 옵션

- 정렬:
  - 최신순
  - 오래된순
- 보기 방식:
  - 카드형
  - 압축형

#### 앨범 탭 옵션

- 정렬:
  - 최신순
  - 오래된순

#### 캘린더 탭 옵션

- 월 이동 유지
- 공유/저장 액션 추가
- 별도 정렬 옵션은 두지 않는다

## 5. 데이터/API 방향

### 5-1. 권장 API

기록 화면은 월별 전용 API를 기준으로 재구성한다.

`GET /api/v1/records/monthly?year=2026&month=6`

### 5-2. 응답 권장 구조

```json
{
  "year": 2026,
  "month": 6,
  "recordsCount": 12,
  "photoCount": 4,
  "photoCoverage": 33,
  "items": [
    {
      "id": 101,
      "recordDate": "2026-06-24",
      "content": "오늘의 장면",
      "oneWordText": "버팀",
      "tomorrowText": "내일의 한 걸음",
      "moodCode": "버팀",
      "imageUrl": null,
      "visibility": "PRIVATE",
      "isPinned": false
    }
  ]
}
```

### 5-3. 이 구조를 추천하는 이유

- 상단 KPI를 서버 응답으로 바로 계산할 수 있다.
- 앨범/기록/캘린더를 하나의 월 응답으로 채울 수 있다.
- 월별 공유 카드 생성 시 필요한 재료를 한 번에 확보할 수 있다.
- 전체 기록을 매번 프론트에서 다시 필터링하지 않아도 된다.

## 6. 프론트 구현 방향

### 6-1. RecordsView

- 진입 시 `현재 월` 기준 monthly API 호출
- 월 이동 시 `year/month` 변경 후 재호출
- 상단 KPI, 앨범, 기록 리스트, 캘린더를 모두 월 응답 기준으로 갱신

### 6-2. 카드 내보내기

- 프론트에서 공유용 DOM을 별도 컴포넌트로 만든다
- `html-to-image` 또는 유사 방식으로 PNG 생성
- 지원 기기에서는 Web Share API 사용
- 미지원 환경에서는 이미지 저장으로 fallback

### 6-3. 공유 대상 우선순위

1. 단건 기록 카드
2. 월간 캘린더 카드
3. 선택 기록 묶음 카드

## 7. 구현 우선순위

### 1순위

- 월별 records API 추가
- RecordsView를 월별 API 기준으로 바인딩

### 2순위

- 단건 기록 카드 내보내기
- 월간 캘린더 카드 내보내기

### 3순위

- 기록 탭 정렬/보기 방식 옵션 추가
- 선택 기록 묶음 카드 확장

### 4순위

- 필요 시 카카오톡 공유 연결

## 8. 제외 또는 후순위 범위

- 공개 링크 복사
- 서버 렌더 기반 이미지 생성
- 공유 이력 저장
- 외부 공개 페이지 생성

## 9. 추천 결론

- 링크 복사는 제거한다.
- 공유 기능은 `카카오톡 공유`보다 `카드 내보내기` 중심으로 설계한다.
- 현재 시점에서 가장 먼저 해야 할 일은 월별 API와 프론트 바인딩 정리다.
- 공유 기능은 그 다음에 단건/월간 캘린더 이미지 내보내기부터 붙이는 것이 가장 안전하다.
