# MR 규칙

## 기본 원칙

- MR은 기능 단위로 올린다.
- 하나의 MR에는 하나의 목적만 담는다.
- 관련 없는 리팩토링, 포맷 변경, 실험 코드는 섞지 않는다.
- 리뷰어가 한 번에 이해할 수 있는 크기로 나눈다.

## 제목 규칙

- MR 제목은 한글로 작성한다.
- 제목은 한 줄로 작성하고 30자 내외로 맞춘다.
- 제목 끝에 마침표를 쓰지 않는다.
- 제목은 작업 목적이 바로 드러나야 한다.

## 본문 필수 항목

- 작업 내용
- 확인 방법
- 영향 범위
- 남은 작업 또는 주의사항

## 본문 예시

```md
## 작업 내용
- 기록 생성 시 mood_code 저장 로직 추가
- 오늘 기록 조회 응답에 moodCode 필드 반영

## 확인 방법
- 기록 생성 API 호출 후 응답의 moodCode 확인
- 오늘 기록 조회 시 동일 값이 내려오는지 확인

## 영향 범위
- 기록 생성 API
- 기록 조회 API

## 남은 작업
- 프론트 기록 작성 화면과 API 연동 필요
```

## MR 올리기 전 체크

- 테스트가 통과하는지 확인한다.
- 디버그 코드, 임시 로그를 제거한다.
- 불필요한 파일 변경이 없는지 확인한다.
- 문서 변경이 필요한 경우 함께 반영한다.

## 금지 항목

- 관련 없는 기능 변경을 한 MR에 같이 올리지 않는다.
- 대규모 포맷 변경을 기능 MR에 섞지 않는다.
- 설명 없이 큰 구조 변경을 올리지 않는다.
