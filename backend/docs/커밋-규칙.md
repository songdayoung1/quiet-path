# 커밋 규칙

## 기본 원칙

- 커밋은 기능별로 나눈다.
- 한 커밋에는 하나의 기능 또는 하나의 수정 목적만 담는다.
- 커밋 메시지는 `feat : `, `fix : `, `refactor : `, `docs : `, `test : ` 중 하나로 시작한다.
- 커밋 메시지는 한글로 작성한다.
- 커밋 메시지에 AI 작업 내역, AI 언급, 생성 도구 언급은 남기지 않는다.
- 기능 추가와 리팩토링은 가능하면 분리한다.
- 제목은 한 줄로 작성하고 30자 내외로 맞춘다.
- 제목 끝에 마침표를 쓰지 않는다.
- 테스트가 실패하는 상태로 커밋하지 않는다.
- 불필요한 포맷 변경은 기능 커밋에 섞지 않는다.

## 메시지 형식

- 형식: `타입 : 작업 내용`
- 예시: `feat : 알림 읽음 처리 추가`
- 예시: `feat : 기록 무드 저장 기능 추가`
- 예시: `fix : 기록 수정 시 중복 생성 오류 수정`
- 예시: `docs : ERD 방향 용어 기준 정리`
- 예시: `test : 알림 읽음 처리 테스트 추가`

## 커밋 본문 규칙

- 본문은 필요한 경우에만 작성한다.
- 본문은 기능별 항목을 하이픈(`-`)으로 정리한다.
- 각 항목은 1~2줄로 간단히 작성한다.

## 본문 예시

```md
feat : 기록 무드 저장 기능 추가

- 기록 생성 시 mood_code 저장 로직 추가
- 오늘 기록 조회 응답에 moodCode 필드 포함
```
